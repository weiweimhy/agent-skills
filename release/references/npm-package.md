# Node.js 包与 CLI 消费者兼容性检查

当发布或改动会影响 Node.js 包使用者或 CLI 调用方时按需核对：

1. **确认既有约束**：先检查 `package.json`、锁文件、声明的 `engines` Node 版本、模块类型（ESM/CJS）、打包配置与 CI 脚本；不切换包管理器，不擅自升级依赖或推断必须双模块支持。
2. **核对公开入口与制品内容**：改动 `exports`、`main`、`module`、`types`、`bin`、`files`、`engines` 或 workspace 配置前，追踪已知消费者与实际发布产物；确认入口文件被正确打包、CLI 的 shebang 与执行权限保留，以及参数、标准输入输出、退出码未发生破坏性变化。
3. **隔离制品消费验证**：避免被 workspace 符号链接掩盖遗漏文件。将实际打包制品（如 `npm pack` 生成的 tarball）安装到临时消费目录，在已声明支持的 Node 版本下执行代表性的导入与 CLI 用例。
4. **报告事实**：记录使用的包管理器、Node 版本、制品版本、消费方式、退出码及未覆盖的兼容范围。
