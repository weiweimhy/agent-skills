# Codex 与 Antigravity 协作开发

本技能保留历史标识 `gpt-agy-collaboration`，兼容旧的显式点名。
主 Agent 与执行 Agent 可由 Codex 或 Antigravity 任一方担任，不预设固定方向。

## 何时协作

- 用户点名本技能，或要求 Codex 与 Antigravity 配合探索、实现、交接或交叉审查时使用。
- 普通问答直接回答，不为协作而拆分。优先遵循用户指定分工；否则按验收所需总费用和耗时，计入交接、返工和验证成本。

## 分工与工具适配

- 主 Agent 负责目标、边界、关键决策和最终验收；执行 Agent 完成边界明确的探索、实现和验证。根因不明时由主 Agent 先收窄问题。
- 先检查当前环境实际可用的代理、MCP、应用或命令行入口及其能力、授权和工作区访问。依照真实接口调用并核对返回状态；不假设工具名、参数、宿主间文件共享或任务会持续运行。
- 原生入口不适用或未获授权时，提供标明“待转交”的任务单。不得声称已发送任务、已连接对方或已运行验证。
- 默认不让执行 Agent 继续委派。每个文件同一时刻只有一个写入者；并行前确认写入范围、接口依赖和共享资源不冲突。

## 跨宿主交接与恢复

- 交接前确认双方拿到同一代码状态。不同宿主或工作区应记录仓库、分支、基线提交，以及双方可访问的提交引用或补丁；不假定本地文件自动同步。
- 为异步或可能中断的任务保留可恢复摘要：任务/代理 ID（若有）、宿主、基线、当前状态、改动路径、最后回执和验证结果。使用已有且获准的持久记录位置；没有持久化能力时将摘要留在当前会话，并标明待转交或待回传。
- 恢复时先读取摘要、检查实际分支和 diff，再继续；摘要可能过期，不能仅凭旧回执认定状态未变。

## 独立交叉审查

- 有独立审查者时，先向审查者提供目标、验收条件、基线、实际 diff 和必要上下文；暂不提供执行 Agent 的解释、自评或测试报告。
- 审查者先记录具体反例、失败路径、触发条件和待确认点，再接收执行报告。之后对照报告检查实际代码和验证证据；不能因执行 Agent 声称测试通过而略过独立发现。
- 若工具不能隔离审查上下文，先记录审查者的初步发现，再查看执行报告。没有独立审查能力时，由主 Agent 单独审查并如实标明限制。

## 任务单与回执

任务单说明目标与独立验收条件、必要背景和路径、基线/补丁引用、可写与禁止范围、接口依赖、验证命令或查找方式及回传格式。不要要求重复已完成的探索。

回执说明实际改动与行为变化、带基线的 diff 或提交引用、实跑命令及结果、未验证项和待决事项。出现越界或需扩大范围时先回报证据并由主 Agent 协调。同一问题经过两轮定向修复仍失败时停止追加尝试，返回失败证据和已排除原因。

## 主 Agent 独立验收

- 检查实际 diff、关键逻辑和验证证据；跨宿主时确认交付物对应约定基线。
- 复用对最终状态仍有效的检查，针对变更补足覆盖缺口；整合多项成果后再做必要的集成检查。
- 独立于执行 Agent 的自我报告作出结论。区分已完成、待转交和未验证；只报告实际使用的工具、模型、命令和结果。
