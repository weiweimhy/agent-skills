# Data, Concurrency, and Stateful Change Checks

只在改动涉及数据库迁移、缓存/分布式锁、批量操作、重试恢复或运行时配置加载时按需核对：

## 数据库 Schema 与数据迁移

- **发布窗口兼容性**：把迁移视为跨版本发布，检查旧应用与新 schema、新应用与旧 schema 在灰度/滚动期间能否并存（必要时采用 expand–migrate–contract），兼容阶段不立即删旧列、改枚举含义或收紧旧版本仍在写入的约束。
- **锁与长事务风险**：结合目标数据库版本和数据规模评估 DDL 锁、索引构建与表重写；大规模回填须分批、可暂停且可幂等续跑。
- **恢复语义**：不假定所有变更都能靠简单 down migration 无损回滚；不可逆变更须确认备份、快照或补偿方案，并在接近目标版本的隔离库验证升级路径。

## 缓存、Redis 与并发协调

- **Key 与降级契约**：核对命名空间、版本、编码与写读方；避免用户输入直接拼接无边界 key；区分“缓存未命中”与“缓存错误”，明确依赖不可用时的退化策略。
- **原子性与锁租约竞争**：多命令更新默认非原子（计数、去重、限流、状态迁移需用原子命令/事务/脚本）。分布式锁须有唯一持有者标识与安全释放校验；核查“旧持有者超时 → 新持有者接管 → 旧持有者延迟完成”时不会误删新锁或覆盖新数据。

## 部分失败、重试与运行时配置

- **部分成功与幂等性**：批量操作部分失败时，确认已持久化结果是否可识别、能否仅重试失败项；不得对非幂等操作默认整批重跑，也不得仅靠重试循环掩盖不确定状态。
- **重试预算与跨字段配置冲突**：沿真实启动入口追踪默认值、配置文件与环境变量覆盖，检查单次超时、最大尝试次数、退避与总时限之间的跨字段约束（例如 `attempt_timeout * max_attempts` 超出总 deadline 时是否被启动校验拒绝或按剩余时限截断）。
