# Agent 行为评测

## 适用范围

用户要求衡量或比较 Agent、提示词、工具/技能路由、拒答与澄清行为、输出格式或任务完成质量时使用。普通程序逻辑测试不等同于 Agent 评测；只需优化提示词时，除非用户也要求测量效果，否则不自动构造完整评测系统。

## 先定义评测对象

开始前固定要评估的系统边界和问题：Agent 版本、提示词、技能/工具集合、运行参数、输入上下文、是否可联网、评测预算，以及结果将支持什么决定。对比不同版本时，除待比较因素外保持条件一致；完整记录模型/服务版本及日期，因为托管模型会变化。

构造能代表真实请求分布的案例，并覆盖边界和容易混淆的邻近任务。每个案例包括唯一 ID、提供给被测 Agent 的任务输入和必要上下文。评测集的版本、抽样来源和已知偏差应可追溯；使用合成数据时明确标记。

## 分开看路由和行为

分别评分两个维度，避免一个总分掩盖失败原因：

- **路由**：是否选择预期技能、工具、流程或拒绝路由。按案例统计正确率和错误去向；适用时同时关注错误触发和漏触发。
- **行为**：选择该路由后，回复是否完成任务并满足约定的关键要求，例如引用可观察证据、说明不确定性、遵守副作用边界、询问缺失条件或使用指定格式。规则必须能从最终回复、工具调用记录或其他可审计产物中判定。

在执行前写明各项指标的定义、分母、通过门槛和排除规则。对风格或复杂语义采用人工盲评、双人复核或独立模型裁判，并保存对应原始产物、rubric 版本和分歧处理；不要把模型自报的“通过”当作独立证据。单元格结果、路由结果与用户任务成功率不要混为一个分数。

## 隔离隐藏答案

将被测 Agent 可见的任务/输入与评测器独有的期望路由、行为要求、参考答案或评分线索分开保存。执行前不要把答案键、判分提示、隐藏文件路径或包含期望标签的工具输出注入被测上下文；生成模型响应后再由独立判分流程读取答案键。

文件改名、隐藏目录、提示词约定或单独的命令行参数都不构成安全隔离。若 Agent 与评测器共享文件系统、进程或工具权限，评测器专属答案仍可能被读取；要测试保密性，就使用真正的进程/权限/容器边界或把判分移到另一环境。仓库中的合成示例答案只演示格式，不是保密机制，也不应含任何真实答案或个人数据。

## 区分真实运行与夹具

- 真实运行记录实际被测 Agent 的版本、配置、时间、完整请求/响应与工具轨迹的可定位证据引用。只要没有实际调用目标 Agent，就不得标记为真实运行。
- 合成夹具、mock、录制回放、人工编写的响应和预置 JSON 结果用于验证评测器、格式或流水线。显式标记为 `fixture`，不得纳入真实运行质量结论。
- 人工或自动行为标注要说明标注方法和依据。标注结果不是原始 Agent 输出；保存可以复核的记录。
- 本技能自带的本地工具仅对结构化结果和答案键做确定性比对，不调用模型，也不能证明标记为 `live` 的记录确由真实 Agent 产生。
  `--require-live` 只检查声明字段；真实性仍需核查引用的原始轨迹。

## 本地确定性验收工具

仓库中的 `scripts/evaluate.py` 仅依赖 Python 标准库，默认读入三个无敏感信息的合成示例文件：

- `examples/cases.json`：被测任务输入，不含预期答案。
- `examples/fixture-run.json`：明确标记为夹具的结构化观察。
- `examples/answer-key.json`：仅由评分端使用的合成期望路由和行为规则。

示例含有普通文本转换任务，答案键中的 `none` 表示不需要选择专项技能，用于观察路由器是否过度触发。

从仓库根目录运行 `python agent-evals/scripts/evaluate.py`。指定自己的评测文件时传入 `--cases`、
`--run` 和 `--key`；
仅在检查实际运行时加 `--require-live`。退出码为 `0` 表示结构有效且所有案例的路由与行为规则均通过，
`1` 表示评测失败或 `--require-live` 与运行声明不符，`2` 表示输入或结构无效。

工具的 `observed_behaviors` 是评测员或明确的规则检查器对原始响应作出的结构化记录；工具不会解析自然语言或替代语义裁判。
反馈给 Agent 的评测结果不得包含尚未公开的答案键或隐藏判分线索。

## 交付

说明评测对象和版本、案例来源与覆盖、评测条件、路由分数、行为分数、原始证据位置、人工/自动标注方式及结果限制。将夹具验收和真实 Agent 运行分段呈现；没有真实运行证据时，不推断模型能力或生产表现。
