# Agent 行为评测

## 适用范围

用户要求衡量或比较 Agent、提示词、工具/技能路由、拒答与澄清行为、输出格式或任务完成质量时使用。普通程序逻辑测试不等同于 Agent 评测；只需优化提示词时，除非用户也要求测量效果，否则不自动构造完整评测系统。

## 定义评测对象

开始前固定要评估的系统边界和问题：Agent 版本、提示词、技能/工具集合、运行参数、输入上下文、联网条件、评测预算，以及结果将支持什么决定。对比不同版本时，除待比较因素外保持条件一致；记录模型/服务版本和日期，因为托管模型会变化。

案例应代表真实请求分布，并覆盖边界和容易混淆的邻近任务。记录唯一 ID、被测任务和必要上下文；保留评测集版本、抽样来源与已知偏差。合成数据应明确标记。

## 两种任务模式

- **明确调用技能**：用户明确点名某技能时，评测必须确认该技能已加载。
  默认允许同时加载其他技能；只有答案键明确声明
  `route_policy: "exact"` 时，才要求实际技能集合完全匹配
  `expected_skills`。
- **自然任务**：用户用普通任务语言提出需求，没有点名技能。评分以可观察
  行为为主；实际加载零个、一个或多个技能都可以。默认只记录技能路由，
  不判路由对错。只有答案键明确声明 `must_include` 或 `exact` 路由策略
  时，路由才计入通过条件。

v2 案例用 `evaluation_mode` 标记模式。明确调用还要在案例中填写
`invoked_skill`。运行记录使用 `selected_skills` 数组。答案键可为路由声明：
`must_include` 要求列出的技能都出现但允许额外技能；`exact` 要求技能集合
完全一致，且必须提供 `expected_skills`。自然任务可以用空数组明确要求
不加载技能。`must_include` 必须列出至少一个技能。自然任务省略路由策略
即为信息记录。明确调用省略策略时，默认要求点名技能并允许额外技能。

v1 套件保持原有语义：每个案例仍将 `selected_route` 与 `expected_route`
作严格相等比较，且路由和行为都必须通过。新建套件使用 v2。

## 独立评分行为与路由

分开报告路由和行为，不用一个总分掩盖失败原因。自然任务中未声明路由政策时，路由只作信息，不进入路由分母；行为项仍按全部案例评分。明确调用技能和已声明路由政策的案例按对应规则判路由。

行为标准应能从最终回复、工具调用记录或其他可审计产物中判定，例如是否
完成任务、引用可观察证据、说明不确定性、遵守副作用边界、询问缺失条件
或使用指定格式。执行前写明指标、分母、通过门槛和排除规则。对风格或复杂
语义使用人工盲评、双人复核或独立模型裁判，并保存原始产物、rubric 版本和
分歧处理；不要把模型自报的“通过”当成独立证据。

提示词对比要固定任务和用户输入，再对照同一行为标准。例如，用户输入
固定为“我的包裹已损坏”。提示词 A 是“尽量帮用户解决问题”，提示词 B 是
“先确认损坏情况，再给出已核实且可执行的下一步”。行为标准是“承认问题、
先收集必要信息、不承诺未经核实的退款”。分别运行 A、B，并按这些行为逐项
判分。静态推演可以验证评分规则，但不能证明提示词的实际效果。

## 隔离答案键

将被测任务/输入与评测器独有的期望路由、行为要求、参考答案或评分线索分开保存。执行前不要把答案键、判分提示、隐藏文件路径或包含期望标签的工具输出注入被测上下文；生成响应后再由独立判分流程读取答案键。

文件改名、隐藏目录、提示词约定或单独的命令行参数都不构成安全隔离。若 Agent 与评测器共享文件系统、进程或工具权限，答案键仍可能被读取；要测试保密性，就使用真正的进程/权限/容器边界，或把判分移到另一环境。仓库中的合成示例只演示格式，不是保密机制，也不应含真实答案或个人数据。

## 区分真实运行与夹具

- 真实运行记录实际被测 Agent 的版本、配置、时间、完整请求/响应与工具轨迹的可定位证据引用。只要没有实际调用目标 Agent，就不得标记为真实运行。
- 合成夹具、mock、录制回放、人工编写的响应和预置 JSON 结果用于验证评测器、格式或流水线。显式标记为 `fixture`，不得纳入真实运行质量结论。
- 人工或自动行为标注要说明标注方法和依据。标注结果不是原始 Agent 输出；保存可复核记录。
- 本地工具只对结构化结果和答案键做确定性比对，不调用模型，也不能证明 `live` 记录确由真实 Agent 产生。`--require-live` 只检查声明字段；真实性仍需核查引用的原始轨迹。

## 本地确定性验收工具

工具仅依赖 Python 标准库，默认读取以下合成 v2 文件：

- `examples/cases.json`：被测任务输入，不含预期答案。
- `examples/fixture-run.json`：明确标记为夹具的结构化观察。
- `examples/answer-key.json`：仅由评分端使用的合成期望路由和行为规则。
- `examples/legacy-v1/`：用于回归旧版严格路由语义的 v1 文件。

从仓库根目录运行 `python agent-evals/scripts/evaluate.py`。CLI 参数和默认
入口保持不变；指定评测文件时传入 `--cases`、`--run` 和 `--key`。仅在检查
实际运行时加 `--require-live`。退出码 `0` 表示结构有效且所有行为和计分
路由规则通过；`1` 表示评分失败或运行声明不符合 `--require-live`；`2` 表示
输入或结构无效。

用 Python 标准库运行评分回归：

```powershell
python -m unittest discover -s agent-evals/tests -v
```

### 重复尝试与组间比较（可选）

若要比较自然任务在 skill 开启/关闭时的表现，或比较主模型直做与委派，保留每次尝试的
v2 单次 run 文件，再用清单分组汇总。自然任务实验可只选 `natural_task` 案例；汇总器也支持
含明确调用或混合模式的 v2 套件，并逐题沿用 `score_v2` 的路由与行为规则。清单中的路径
相对清单文件解析；组名由评测者定义，因此也可加入 `delegated+independent-review` 等第三组。

```json
{
  "schema_version": 1,
  "suite_id": "my-natural-task-suite",
  "comparison_name": "skill availability",
  "groups": ["skill-disabled", "skill-enabled"],
  "runs": [
    {"group": "skill-disabled", "run_file": "runs/off-01.json"},
    {"group": "skill-enabled", "run_file": "runs/on-01.json"}
  ]
}
```

从仓库根目录运行：

```powershell
python agent-evals/scripts/summarize_repeats.py `
  --cases cases.json `
  --key answer-key.json `
  --runs manifest.json
```

每个清单条目引用一个现有 v2 单次 run；每个 run 对每道题贡献一次尝试。单次
`evaluate.py` 接口和已有数据保持不变，仍只负责行为和路由评分；环境门槛与实测指标由
汇总器读取。可在 run 的 `case_results` 项上添加实测字段：

```json
{
  "human_intervention": true,
  "human_intervention_minutes": 2.5,
  "cost_usd": 0.12,
  "time_to_acceptance_seconds": 185,
  "environment_assertions": [
    {"name": "python", "expected": "3.13", "actual": "3.13"}
  ]
}
```

`cost_usd` 是该次尝试中模型、工具、失败调用和返工的总支出；按组的平均通过成本用所有
尝试总支出除以通过数，因此失败尝试的开销也计入。币种固定为 USD。
`time_to_acceptance_seconds` 记录该题从开始到验收的实际墙钟耗时；汇总按通过尝试取平均，
不把并行 worker 的各自耗时相加。成功/尝试数按行为要求、计分路由策略和环境断言共同
判定。使用环境断言时，将以下字段写入答案键中对应的题目，以固定各组的预期值。

```json
{
  "required_environment_assertions": [
    {"name": "python", "expected": "3.13"}
  ]
}
```

缺少必需断言或 `actual: null` 会记为未知并使该次不通过；实际值不符也会使该次不通过。
任何 run 中的环境断言都必须先在答案键定义；未定义的断言会报输入错误，避免某组的记录
决定其他组的预期。可选实测字段缺失一律显示为未知，不作为零值。live 和 fixture 结果分开
展示；`--require-live` 仅核对声明，不能证明来源。汇总入口返回 `0` 表示输入有效并完成
汇总，不代表任务通过。

运行记录中的行为是评测员或明确规则检查器对原始响应作出的结构化标注；工具不会解析自然语言或替代语义裁判。反馈给 Agent 的评测结果不得包含尚未公开的答案键或隐藏判分线索。

## 交付

说明评测对象和版本、案例来源与覆盖、评测条件、行为分数、适用时的路由分数、原始证据位置、人工/自动标注方式及结果限制。将夹具验收和真实 Agent 运行分段呈现；没有真实运行证据时，不推断模型能力或生产表现。
