# 前端设计契约参考

本文件是 `project-standards-init` 的流程参考，不是某个项目已经采用的设计系统。
它帮助初始化任务在有足够输入时记录一份可逆、可验收的前端设计基线。
可以选择适合目标的方案并注明依据，但不自动安装依赖、实现 UI 或制造视觉来源。

## 适用门槛

先判断本轮属于哪一种情况，并在汇总中保留证据：

- **已有 UI**：检查实际页面、样式入口、主题 token、组件 API、图标导入和交互状态。提炼已有范式并沿用，只把可从代码、配置或用户决定追溯的内容写为事实。
- **明确初始化前端**，或用户明确要求统一美观并加入动效：可以依据 brief 建立一份可逆基线。每条新增内容标为“本次设计决策”，说明尚未代表实现，不得把方案写成既成事实。
- **纯审计**：只记录已有事实及缺口，不生成新的风格方案，即使仓库已有完整范式也不自动换肤。
- **没有用户界面且未要求创建前端（例如仅后端）**：不生成前端设计文档。
  已授权新建前端但尚无代码时，使用建立基线分支。

Skill、MCP、浏览器、截图目录或通用笔记的存在不能证明项目已经采用某个风格、图标库、主题、断点或视觉回归工具。外部参考只有在用户提供或项目明确批准后才可记录。

## 单一来源与状态

设计成果只维护一个来源：已有 `DESIGN.md` 时沿用它，否则使用 `docs/ui-design.md`；不要同时新建两份。文档开头记录来源、适用页面、决策日期和证据路径。

每条规则、token、组件状态和验收结论使用以下标签，避免把愿望写成事实：

- `[规范]`：项目已确认的约束或本轮批准的基线。
- `[设计决策-本次]`：根据本次 brief 建立的可逆方案，仍属于规范，未证明已经实现。
- `[已实现]`：能在源码、配置或可运行页面中定位到实现。
- `[待验证]`：目标已经写下，但实现、对比度、设备表现或行为尚未实际检查。

本轮基线要写明组件、token、主题和动效的实现入口；尚未决定时写“待决策”。
可规划未来文件路径并标注“计划／尚未创建”，不能伪装成现有代码证据。后续实现更新同一来源。

## 基线内容

### 目标与避用

记录产品受众、核心任务、页面类型、信息优先级和 3--5 个可检查的视觉词（例如“清晰、克制、快速扫描”）。同时列出明确避用的表达（例如装饰性渐变、过度圆角、层层嵌套卡片或影响阅读的动效），并说明它们服务于什么任务约束；不要套用与产品无关的模板风格。

### Token、字体与密度

先复用项目已有 token。没有既有数值且用户批准建立基线时，可把下面的小型起点写入文档并标为 `[设计决策-本次]`；它们可调整，不是强制标准。

| 语义 token | 可调整的起始值 | 用途 |
| --- | --- | --- |
| `color.bg.canvas` | `#F7F8FA` | 页面背景 |
| `color.bg.surface` | `#FFFFFF` | 内容表面 |
| `color.text.primary` | `#1F2937` | 主要文字 |
| `color.text.secondary` | `#4B5563` | 辅助说明 |
| `color.border.default` | `#D1D5DB` | 分隔与输入边框 |
| `color.action.primary` | `#1D4ED8` | 主要操作 |
| `color.focus.ring` | `#2563EB` | 键盘焦点 |
| `color.status.success` | `#15803D` | 成功 |
| `color.status.warning` | `#B45309` | 警告 |
| `color.status.danger` | `#B91C1C` | 危险 |

这是克制型操作界面的可选示例，不是所有产品默认配色；落地页、阅读页和品牌展示按目标另定。
主题改变语义 token，不在组件中散落颜色。写明支持的主题、切换方式和覆盖范围，
不为没有暗色需求的项目强加暗色。配齐 action 的文字、hover、pressed、disabled、
错误背景和焦点颜色，检查实际相邻背景；普通文字对比度至少 4.5:1，
大字号文字及必要的控件边界、图形至少 3:1，装饰分隔线不代替可识别的控件边界。

字体优先沿用项目已加载字体和中文回退。没有决定时可从 `system-ui` 起步，
依次回退到 `Segoe UI`、`Microsoft YaHei`、`PingFang SC`、`sans-serif`。
记录字重、许可和加载入口，不自动引入远程字体。起始字号/行高（px）可用正文 `14/22`、
标签 `12/18`、小标题 `18/26`、页面标题 `28/36`；按任务调整，阅读正文可从 `16/26` 起步。
验证长中文、英文、数字混排与缩放；换算为可缩放单位时保留层级关系。

可从 `4, 8, 12, 16, 24, 32` px 建立间距刻度，圆角取 `4/8/12` px，按元素角色映射。
阴影可从 `0 1px 2px rgba(15,23,42,.08)` 起步，仅对需要层级分离的表面使用。
记录页面最大宽度、内容边距、栅格、列间距和密度目标；例如常规控件高度从 `40px` 起步，
紧凑数据行从 `36px` 起步，移动操作触摸目标可取 `44px`；长文本允许高度增长。
数值须经过目标内容与设备检查，不以缩小文字或点击区域换取密度。

响应式规则记录哪些列折叠、操作移入菜单、表格转列表、文本换行或保留滚动。
没有断点事实时，可从 `640/768/1024/1280` px 选择必要的点作为待验证起点，
不把它们写成框架默认；同时说明每个断点改变什么，不只列数字。

### 组件、变体与状态

用一张矩阵覆盖高频组件；每行同时写变体、状态、键盘行为和单一实现入口。至少考虑默认、悬停、按下、焦点、禁用、加载、成功、错误、空和权限不足等实际状态，不为不存在的页面补造状态。

| 组件 | 变体 | 必要状态与内容 | 键盘/焦点 | 单一实现入口 |
| --- | --- | --- | --- | --- |
| Button | 主要、次要、危险、图标 | 悬停、按下、禁用、加载 | Enter/Space | Button 导出 |
| Input/Select | 默认、密集、只读 | 输入、错误、禁用、帮助 | 标签关联、按控件定义键盘 | 表单入口 |
| Tab/Nav | 水平、折叠 | 当前、悬停、焦点、禁用、溢出 | 方向键或 Tab 规则须与实现一致 | 路由/导航入口或 `[待验证]` |
| Panel/Dialog | 面板、弹层 | 进入、退出、空、加载、错误 | 焦点进入/返回、Esc | 容器/弹层入口 |
| List/Table | 紧凑、常规 | 加载、空、失败、分页、选中、权限 | 行操作名称、表头与读屏顺序 | 项目现有数据视图入口或 `[待验证]` |

矩阵中的方案若尚未实现，标 `[设计决策-本次]`；已有源码证据才标 `[已实现]`。状态变化不能只靠颜色表达，应同时有文字、图标、结构或可访问状态。
将示例入口替换为实际导出路径或明确标注的计划路径。复用组件库已有无障碍行为；
只封装项目语义与常用变体，不重复手写弹层焦点管理。页面不得复制按钮 CSS 或随意覆盖全局 token。
需要新变体时先扩展共享组件，迁移同类调用；局部例外记录用途和边界，避免第二套组件系统。

### 图标

沿用已采用的图标系统；建立前端基线时可根据框架兼容、视觉语言、许可和包体选择一个主家族，
明确标注本次选择且未安装。纯审计中未知系统写“待决策”，不从组件库推断采用关系。
来源、许可证、版本与静态导入边界必须可追溯；优先按需静态导入，避免无界动态注册或整包引入。
品牌标志或专属业务图形可作为有来源的例外，不混用多套常规图标或用 emoji 代替操作图标。

为搜索、筛选、添加、编辑、删除、关闭、返回等建立“语义→实际图标导出”的映射。
同一语义不因页面换图；尺寸可从 `16/20/24px` 起步，描边沿用主家族并统一视觉重量。
图标按钮有可访问名称，装饰图标对读屏隐藏。Tooltip 不代替可访问名称；
含义不明显的纯图标操作提供提示，记录悬停/焦点触发、触摸替代与共享实现入口。

### 实用交互动画

动画为状态变化服务，文档要写清触发、属性、时长、easing、退出、可中断性和焦点影响。至少覆盖可用控件反馈和一种面板状态过渡：

| 场景 | 触发与属性 | 起始时长/easing | 退出与中断 |
| --- | --- | --- | --- |
| 控件反馈 | 悬停/按下；背景、边框 | `120–160ms` / `ease-out` | 松开可反向，不移走目标 |
| 面板进出 | 开关；透明度、位移 `4–8px` | `160–240ms` / 项目进入曲线 | 退完卸载，可中断反向 |
| 提交状态 | 请求起止；保留布局的反馈 | `120–200ms` / `ease-out` | 失败、取消、超时可退出 |

将时长和曲线统一为 motion token；进入曲线可从 `cubic-bezier(.2,.8,.2,1)` 起步。
退出通常更短，交互响应不能等待动画完成；按现有弹层机制处理焦点进入、返回和退出期间不可交互性。
动画不能隐藏错误、成功、权限或焦点变化；焦点环立即出现并持续可见，Esc 始终可用。
优先 CSS transition/keyframes，复杂中断或手势再复用现有动画库；不为简单淡入安装依赖。
明确 transition 属性，避免 `transition: all`，优先 transform/opacity；布局动画须验证开销。
悬停位移动效限支持 hover 的精细指针；触摸和键盘仍有独立反馈，不以动画阻塞提交。
清理监听、计时器与动画实例；没有脚本或动画结束事件时，内容与业务流程仍可到达最终状态。
`prefers-reduced-motion: reduce` 下移除位移与非必要循环，缩短或置零过渡，保留可读状态和焦点。
高频操作更克制，展示页才按内容需要安排重点动效，不让每段内容都等待滚动显现。
没有实际实现和设备检查时标 `[待验证]`。

## 黄金页面、AGENTS 约束与验收

选择 1–3 个真实高频页面作为黄金页面，记录任务、代表数据、语言、主题、视口与状态。
新项目可以规划一个含列表、表单、按钮、图标和弹层的代表页面，标“计划／未实现”，不虚构截图。
先通过代表页面验证再复用到其余页面；保持内容层级、对齐、留白与主要操作突出。
后续 `AGENTS.md` 按实际路径写入简短规则，例如：

> 修改 UI 前读取视觉规范和交付文档，检查共享 token、组件及代表页面。
> 同类页面复用组件变体、图标语义和 motion token；新增变体先更新共享入口与规范。
> 保持品牌与交互行为，超出授权的全局换肤或库替换先确认。
> 实现需覆盖加载/空/错误/禁用、键盘焦点和减少动态效果；交付报告实际验收与未验证范围。

在 `docs/ui-delivery.md` 记录实际条件、操作和结果；主题/语言只覆盖产品支持的范围：

- 在目标桌面与窄视口检查布局、长文本、溢出和触摸目标，横向比较代表页面的组件与图标。
- 用 Tab/Enter/Space/Esc 完成主任务；检查名称、焦点进入/返回与可见性。
- 触发加载、空、错误、禁用、权限与成功状态，检查文字、布局和可恢复操作。
- 实际打开/关闭面板、快速重复触发或中途反向；确认无跳变、焦点丢失、重复提交或残留遮罩。
- 启用减少动态效果后重复操作，确认状态信息完整、非必要位移消失、退出仍完成。
- 能运行页面时查看真实渲染并修复视觉问题；静态截图不能证明动画顺畅或中断正确。

只报告执行过的命令、浏览器、设备与步骤；无法运行则标待验证并给出以上人工验收路径。
不承诺尚未建立的截图回归、浏览器测试或性能指标。

文档末尾保留“未决策与待验证”表，列出证据、影响、责任人和最小下一步。这样既能让后续实现从同一基线继续，也能在事实改变时撤销本次可逆决策。
