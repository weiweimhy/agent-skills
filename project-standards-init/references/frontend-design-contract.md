# 前端视觉与 UI 基座参考

本参考用于在仓库涉及 Web / 前端 UI 时，建立一份**既保证原生一致感、又不束缚审美创造力**的视觉基座。核心理念借鉴 Twenty、Supabase、Remotion、Storybook、Vercel 与 Anthropic/Impeccable 实践：**工程规范归 `AGENTS.md`，视觉品位归 `DESIGN.md`；用语义 Token、标杆页面和真实渲染验收赋能 AI，而不是用几百行像素禁令制造千篇一律的样板页面。**

## 一、单一权威来源与正交分离

- **不要把视觉细节塞进根 `AGENTS.md`**：保持工程规则与设计语言正交。
- **单一事实源**：先检查仓库是否已有有效设计规范（`DESIGN.md`、`docs/design-system.md`、`docs/ui-design.md` 等）。
  - 已有有效来源：沿用并增量扩展，不建立第二套副本。
  - 尚无设计规范且本轮获授权建立：推荐在根目录建 `DESIGN.md`（若仓库已有清晰 `docs/` 体系，也可放 `docs/ui-design.md`）。
- **两条防漂移声明**（建议写入设计基座顶部）：
  1. **代码是数值真源**：色值、字号、间距具体定义以源码 Token 文件（如 `globals.css` / `tokens.ts`）为准，文档只映射语义角色与用法，避免双处失步。
  2. **新基座优先于历史旧页**：若仓库存在未迁移的历史页面，AI 新增或重构页面时应遵循设计基座与标杆页面，不盲目模仿旧页面技术债。

## 二、按现状选择轻量切入模式

| 仓库现状 | 处理方式 |
| :--- | :--- |
| **无 UI** | 不生成视觉文档。 |
| **已有成熟界面 / 设计系统** | 提炼现有审美方向、语义 Token 入口、标杆页面与组件复用边界，不擅自推翻品牌。 |
| **新项目 / 获授权建立新方向** | 从产品受众、核心任务与信息密度推导清晰、可逆的审美基线；标注“本次确立，可随产品演进调整”。 |
| **仅盘点或产品输入明显不足** | 记录现有 UI 事实与待定方向，不编造虚构的品牌配色或假页面。 |

> **不要预设形态**：网站不默认是 SaaS 后台或 dashboard，也不默认带侧栏、表格操作台或特定 UI 库。按真实产品任务决定页面形态与信息密度。

## 三、高杠杆 `DESIGN.md` 五大核心模块

只写对当前项目真正有用的模块，**不适用项直接省略**（不填“不适用”空表）：

### 1. 产品气质与避用方向（Aesthetic Direction）

- **受众与核心任务**：用户来这里完成什么？信息密度是“高密度工具”“沉浸阅读”还是“品牌叙事”？
- **3–5 个可感知的视觉词**：例如“冷静、高密度、键盘优先”或“克制、纸面质感、留白呼吸”。
- **明确避用（及原因）**：列出与产品气质冲突的表达（如“工具页避免装饰性大面积渐变与多层嵌套卡片，以免分散扫描焦点”）。留出合理视觉发挥空间，不做微观审美说教。

### 2. 语义 Token、字体与主题真源

- **映射语义角色，而非罗列硬编码值**：指明背景、表面、主/辅文字、边框、主操作、焦点与状态色对应的语义 Token 名称及其源码入口；主题切换只改语义 Token。
- **不强塞默认色板**：不要把某套固定十六进制配色当作所有产品的默认。新项目若获授权拟定初始方向，写清设计意图与对比度底线（普通文字 ≥ 4.5:1，大字号与必要控件边界 ≥ 3:1，状态不只靠颜色表达）。
- **字体与排版原则**：记录已采用或选定的字体栈、中文回退与加载边界（不擅自引入未授权远程字体）；给出排版层级与密度原则（如阅读页 vs 密集工作台），把具体尺寸数值留在代码 Token 中维护。
- **支持范围**：浅/深色主题、目标视口与响应式折叠策略只按项目真实支持范围记录；无暗色需求时不强加暗色。

### 3. 标杆页面与按需选组件（最高复用杠杆）

- **标杆页面（Reference Screens / Copy the Sibling）**：列出 2–5 个真实存在的代表页面或组件路径（新项目可记规划入口）。告诉 AI“做同类界面前先看哪个标杆”，远比写百行间距规则有效。
- **按场景选组件表（Need → Use → Instead of）**：只为真实高频易错点建一张精简对照表，例如：

| 场景需求 | 优先复用 | 避免 |
| :--- | :--- | :--- |
| 页面唯一主操作 | `<共享主按钮路径/变体>` | 同屏堆砌多个高强调主按钮 |
| 持久性提示或风险说明 | `<共享 Callout/Alert>` | 用会自动消失的 Toast 承载关键信息 |
| 需要新样式变体 | 先扩展共享组件并同步入口 | 在业务页散落复制 CSS 或硬编码色值 |

- **组件状态**：按页面真实任务覆盖适用状态（如加载、空、错、禁用、焦点、权限），不为纯阅读页虚构表单或弹窗状态。

### 4. 图标、动效与国际化（按需写入，无则省略）

- **图标**：仅当存在跨页面图标体系时，记录主图标家族、按需静态导入方式、常用语义映射与无障碍名称（装饰图标隐藏读屏）；无需求则省略。
- **动效**：优先服务操作反馈与状态过渡，说明动效风格（克制/微交互 vs 展示重点）、可中断性与尊重 `prefers-reduced-motion`；优先用平台/CSS 原生能力，不无故引入重型动效库。无动效规划则省略。
- **国际化**：仅当项目实际支持多语言时，记录翻译入口、键归属、日期/数字/货币格式与长文本换行边界；单语言项目直接省略。

### 5. 真实运行时验收（Verify in the Real Parent）

- **静态检查交给工具**：硬编码颜色、无障碍 lint、类型检查尽可能走 ESLint/Stylelint/Biome 命令。
- **视觉与交互必须真实渲染验收**：在**真实父容器与目标视口/主题**中检查布局、长文本溢出、键盘主流程（Tab/Enter/Space/Esc）、真实交互状态与动效中断；有 Storybook `play`、Playwright 或浏览器验收工具时直接给出可运行命令。
- 静态截图只证明静态外观，不能替代交互与动效检查；无法运行界面时如实记录未验范围与人工验收路径。

## 四、根 `AGENTS.md` 中的最小前端衔接

在根 `AGENTS.md` 只需保留 2–4 行路由与底线，不复制 `DESIGN.md` 全文：

> - 涉及 UI / 样式改动前，先读 `DESIGN.md`（或实际设计文档）及同类标杆页面，复用共享语义 Token 与组件入口，不散落硬编码色值。
> - 授权范围内的页面布局与交互细节可自主打磨；全局换肤、更换 UI 库或推翻既有品牌方向前先确认。
> - UI 改动完成后，在真实渲染环境中核查目标视口、关键状态与键盘焦点，并如实报告验收范围。
