# 前端设计契约参考

本文件是 `project-standards-init` 的流程参考，不是某个项目已经采用的设计系统。
它帮助初始化任务在有足够输入时记录一份可逆、可验收的前端设计基线。
可以选择适合目标的方案并注明依据，但不自动安装依赖、实现 UI 或制造视觉来源。

## 范围与前提

前端分支、文档生成条件和适用范围由
[前端分支与文档判定](document-contract.md#前端分支与文档判定) 决定。
本文件仅记录已选择范围内的前端设计内容：目标与避用、token、组件与状态、
图标、实际或已批准规划的动效，以及代表页面与验收方式。它不重复分支判断，
也不为未选择的页面类型补造规范。
下文的规划范围包括用户已批准的计划，以及本轮授权内按统一判定建立的可逆设计决定；
尚未实现的项目可记录计划，不要求已有代码才允许制定规范。

## 单一来源与状态

先查找能够覆盖目标页面的现有设计规范，确认其适用页面、有效决定和冲突。
已有 `DESIGN.md`、`docs/design-system.md`、`docs/ui-design.md` 或其他等价有效规范时，
沿用其中唯一的权威来源；新页面应在同一来源中扩展，或在来源中明确适用边界。
只有找不到可用来源时才新建 `docs/ui-design.md`，不得复制第二份权威规范。
记录来源文件、适用页面、决定日期和证据路径；Skill、MCP、浏览器、截图目录或通用
笔记的存在不能证明项目已经采用某个风格、图标库、主题、断点或视觉回归工具。

每个章节或表格开头记录以下三个独立维度，避免把愿望写成事实：

| 维度 | 可用值 | 记录方式 |
| --- | --- | --- |
| 来源 | 既有／本次决定 | 说明事实依据或批准决定，以及适用范围 |
| 实现 | 已实现／待实现 | 写明源码、配置或计划入口；没有入口就保留为计划 |
| 验证 | 已验／未验 | 记录实际执行的页面、设备、命令或人工步骤 |

状态默认按章节或表格集中记录；只有局部例外才逐条标记。保留证据路径，区分已确认
事实、本次可逆决定、计划和未完成检查，不把计划或工具能力写成实现或验证结果。

## 基线内容

### 目标与避用

记录产品受众、核心任务、页面类型、信息优先级和 3--5 个可检查的视觉词（例如“清晰、克制、快速扫描”）。同时列出明确避用的表达（例如装饰性渐变、过度圆角、层层嵌套卡片或影响阅读的动效），并说明它们服务于什么任务约束；不要套用与产品无关的模板风格。

### Token、字体与密度

先复用项目已有 token。没有既有数值且用户批准建立基线时，可把下面的小型起点写入文档，
并在本节状态中记录为“来源：本次决定”；它们可调整，不是强制标准。
本节集中记录 token、字体、密度和响应式规则的来源、实现和验证，避免给每个 token 重复贴标签。
本节的 CSS token 写法、`px` 数值和响应式断点仅适用于 Web/WebView；
原生桌面、Unity 等复用相同的抽象设计原则，映射到实际平台尺寸单位、布局能力和设备检查，
不产生 CSS 依赖。

| 语义 token | 可调整的起始值 | 用途 |
| --- | --- | --- |
| `color.bg.canvas` | `#F7F8FA` | 页面背景 |
| `color.bg.surface` | `#FFFFFF` | 内容表面 |
| `color.text.primary` | `#1F2937` | 主要文字 |
| `color.text.secondary` | `#4B5563` | 辅助说明 |
| `color.border.divider` | `#D1D5DB` | 仅装饰分隔，不作为必要控件边界 |
| `color.border.control` | `#6B7280` | 可选的独立控件边界；按实际相邻背景验证 |
| `color.action.primary` | `#1D4ED8` | 主要操作 |
| `color.focus.ring` | `#2563EB` | 键盘焦点 |
| `color.status.success` | `#15803D` | 成功 |
| `color.status.warning` | `#B45309` | 警告 |
| `color.status.danger` | `#B91C1C` | 危险 |

这是克制型操作界面的可选示例，不是所有产品默认配色；落地页、阅读页和品牌展示按目标另定。
主题改变语义 token，不在组件中散落颜色。写明支持的主题、切换方式和覆盖范围，
不为没有暗色需求的项目强加暗色。配齐 action 的文字、hover、pressed、disabled、
错误背景和焦点颜色，检查实际相邻背景；普通文字对比度至少 4.5:1，
大字号文字及必要的控件边界、图形至少 3:1，装饰分隔线不代替可识别的控件边界。
本示例中，`#D1D5DB` 与 `#FFFFFF` 的对比度为 1.47:1，因此只用于装饰分隔；
可选的 `#6B7280` 控件边界与 `#FFFFFF` 的对比度为 4.83:1，
与 `#F7F8FA` 的对比度为 4.55:1，均满足 3:1。
上述计算只覆盖所列白色表面和画布，其他主题及相邻背景仍须逐一验证，
不代表所有主题已验证。

字体优先沿用项目已加载字体和中文回退。没有决定时可从 `system-ui` 起步，
依次回退到 `Segoe UI`、`Microsoft YaHei`、`PingFang SC`、`sans-serif`。
记录字重、许可和加载入口，不自动引入远程字体。起始字号/行高（px）可用正文 `14/22`、
标签 `12/18`、小标题 `18/26`、页面标题 `28/36`；按任务调整，阅读正文可从 `16/26` 起步。
验证长中文、英文、数字混排与缩放；换算为可缩放单位时保留层级关系。

可从 `4, 8, 12, 16, 24, 32` px 建立间距刻度，圆角取 `4/8/12` px，按元素角色映射。
阴影可从 `0 1px 2px rgba(15,23,42,.08)` 起步，仅对需要层级分离的表面使用。
记录页面最大宽度、内容边距、栅格、列间距和密度目标；例如常规控件高度从 `40px` 起步，
紧凑数据行从 `36px` 起步，移动操作触摸目标可取 `44px`；长文本允许高度增长。
数值须经过目标内容与设备检查，不以缩小文字或点击区域换取密度。

响应式规则记录哪些列折叠、操作移入菜单、表格转列表、文本换行或保留滚动。
没有断点事实时，可从 `640/768/1024/1280` px 选择必要的候选点，
不把它们写成框架默认；同时说明每个断点改变什么，不只列数字。

### 组件、变体与状态

只把实际存在或已批准规划的高频组件放入矩阵；每行记录该组件实际需要的变体、状态、
键盘行为和单一实现入口。按页面需要选择默认、悬停、按下、焦点、禁用、加载、成功、
错误、空或权限状态，不为不存在的页面补造状态。阅读站可只记录真实导航链接、正文和
内容反馈，不强制表单、表格、权限或弹层。
矩阵中的 Tab/Enter/Space/Esc 是 Web/WebView 的焦点键示例；原生桌面、Unity 等按平台实际
输入与焦点模型映射并验证。

| 组件 | 变体 | 必要状态与内容 | 键盘/焦点 | 单一实现入口 |
| --- | --- | --- | --- | --- |
| Button | 主要、次要、危险、图标 | 悬停、按下、禁用、加载 | Enter/Space | Button 入口 |
| Input/Select | 默认、密集、只读 | 输入、错误、禁用、帮助 | 标签关联、按控件定义键盘 | 表单入口 |
| Link/Nav | 真实导航、当前页、折叠等 | 当前、悬停、焦点、溢出等实际状态 | Tab 或平台等效输入 | 实际路由/导航入口 |
| Panel/Dialog | 面板、弹层 | 进入、退出、加载、错误 | 焦点进出、Esc | 容器/弹层入口 |
| List/Table | 紧凑、常规 | 加载、空、失败、分页、选中 | 行操作名称、表头与读屏顺序 | 数据视图入口 |

在矩阵前集中记录组件范围的来源、实现和验证；某一行的例外再单独说明。
状态变化不能只靠颜色表达，应同时有文字、图标、结构或可访问状态。
将示例入口替换为实际导出路径或明确标注的计划路径。复用组件库已有无障碍行为；
只封装项目语义与常用变体，不重复手写弹层焦点管理。页面不得复制按钮 CSS 或随意覆盖全局 token。
需要新变体时先扩展共享组件，迁移同类调用；局部例外记录用途和边界，避免第二套组件系统。

### 图标

沿用已采用的图标系统；建立前端基线时可根据框架兼容、视觉语言、许可和包体选择一个主家族，
在本节状态中记录其来源、实现和验证；尚未选择的系统写“待决策”，不从组件库推断采用关系。
来源、许可证、版本与静态导入边界必须可追溯；优先按需静态导入，避免无界动态注册或整包引入。
品牌标志或专属业务图形可作为有来源的例外，不混用多套常规图标或用 emoji 代替操作图标。

为搜索、筛选、添加、编辑、删除、关闭、返回等建立“语义→实际图标导出”的映射。
同一语义不因页面换图；尺寸可从 `16/20/24px` 起步，描边沿用主家族并统一视觉重量。
图标按钮有可访问名称，装饰图标对读屏隐藏。Tooltip 不代替可访问名称；
含义不明显的纯图标操作提供提示，记录悬停/焦点触发、触摸替代与共享实现入口。

### 实用交互动画

只记录实际存在或上述规划范围内的交互动画；页面没有面板时不要求面板过渡，
没有提交交互时不保留提交状态。对每个实际动效写清触发、属性、时长、easing、退出、
可中断性和焦点影响，并在本节集中记录来源、实现和验证。表中的 `px` 位移、`ease-out`
和 easing 曲线是 Web/WebView 示例；原生/Unity 只复用时长、反馈和可中断等抽象原则，
映射到实际尺寸单位和动画运行时曲线：

| 交互（按实际范围保留） | 触发与属性 | 起始时长/easing | 退出与中断 |
| --- | --- | --- | --- |
| 控件反馈 | 实际悬停/按下交互；背景、边框 | `120–160ms` / `ease-out` | 松开可反向，不移走目标 |
| 面板进出 | 存在或已批准规划的面板开关；透明度、位移 `4–8px` | `160–240ms` / 项目进入曲线 | 退完卸载，可中断反向 |
| 提交状态 | 存在或已批准规划的请求起止；保留布局的反馈 | `120–200ms` / `ease-out` | 失败、取消、超时可退出 |

将时长和曲线统一为 motion token；Web/WebView 的进入曲线可从
`cubic-bezier(.2,.8,.2,1)` 起步，原生/Unity 使用实际动画运行时的等效曲线。
退出通常更短，交互响应不能等待动画完成；存在弹层时按现有机制处理焦点进入、返回和退出期间不可交互性。
动画不能隐藏实际存在的错误、成功、权限或焦点变化；各平台的焦点指示应立即出现并持续可见，
Web/WebView 中 Esc 始终可用，原生/Unity 按平台返回/取消输入映射。
Web/WebView 可优先使用 CSS transition/keyframes，复杂中断或手势再复用现有动画库；
原生/Unity 使用项目已有动画运行时实现相同的状态、时长、可中断性和焦点要求，
不产生 CSS 依赖。
Web/WebView 明确 transition 属性，避免 `transition: all`，优先 transform/opacity；
原生/Unity 采用对应运行时的属性和布局机制；各平台的布局动画均须验证开销。
Web/WebView 的悬停位移动效限支持 hover 的精细指针，原生/Unity 按平台指针能力映射；触摸和键盘/平台输入仍有独立反馈，不以动画阻塞提交。
清理平台对应的监听、计时器与动画实例；没有可用的动画结束回调时，内容与业务流程仍可到达最终状态。
存在动效时，Web/WebView 在 `prefers-reduced-motion: reduce` 下移除位移与非必要循环，
缩短或置零过渡，保留可读状态和焦点；原生/Unity 映射到实际系统的减少动态效果能力或项目设置，
确认没有对应能力时记为 `未支持/待补齐`，不虚构系统支持。
高频操作更克制，展示页才按内容需要安排重点动效，不让每段内容都等待滚动显现。
既无现有动效，也无本次决定或已批准规划的动效时可省略动效规范；已有或已批准规划的动效若尚未检查，
在本节验证状态中记录“未验”并给出最小检查步骤。

## 黄金页面、AGENTS 约束与验收

选择 1–3 个实际存在或已批准规划的代表页面（若本轮范围包含页面），记录任务、代表数据、
语言、主题、视口和实际状态。没有可运行页面时记录计划范围，不虚构页面或截图。
阅读站选择真实阅读页、目录页和导航链接作为代表范围，不补造表单、表格、权限或弹层。
先通过代表页面验证再复用到其余页面；保持内容层级、对齐、留白与主要操作突出。
本节按章节或表格记录来源、实现和验证；局部例外单独说明。
后续 `AGENTS.md` 按实际路径写入简短规则，例如：

> 修改 UI 前读取视觉规范和交付文档，检查共享 token、组件及代表页面。
> 同类页面复用实际存在的组件变体、图标语义和 motion token；新增变体先更新共享入口与规范。
> 保持品牌与交互行为，超出授权的全局换肤或库替换先确认。
> 按页面实际状态覆盖加载、空、错误、禁用、键盘焦点和减少动态效果；不适用的状态注明不适用，交付报告实际验收与未验范围。

在统一判定选定的交付文档中记录实际条件、操作和结果；主题/语言只覆盖产品支持的范围：

- 在 Web/WebView 的目标桌面与窄视口，或原生/Unity 的目标窗口与屏幕尺寸，检查布局、长文本、溢出和触摸目标，横向比较代表页面的组件与图标。
- 对实际导航和控件用 Web/WebView 的 Tab/Enter/Space/Esc 完成主任务；原生/Unity 使用平台实际输入，检查名称、焦点进入/返回与可见性。
- 仅触发本次范围内实际存在或已批准规划的加载、空、错误、禁用、权限和成功状态，检查文字、布局和可恢复操作。
- 存在面板或弹层时，实际打开、关闭、快速重复触发或中途反向；确认无跳变、焦点丢失、重复提交或残留遮罩。
- 存在动效时，Web/WebView 启用 `prefers-reduced-motion`；原生/Unity 启用平台系统的减少动态效果能力
  或项目对应设置后重复操作，确认状态信息完整、非必要位移消失、退出仍完成；
  平台没有对应能力时记录 `未支持/待补齐`，仍检查状态完整和退出可用。
- 能运行目标 UI 时查看真实渲染并修复视觉问题；静态截图不能证明动画顺畅或中断正确。

只报告执行过的命令、浏览器、设备与步骤；无法运行则在验证状态记录“未验”，并给出以上人工验收路径。
不承诺尚未建立的截图回归、浏览器测试或性能指标。

文档末尾保留“未决策与待验证”表，列出来源、实现、验证、证据、影响、责任人和最小下一步；
这样既能让后续实现从同一基线继续，也能在事实改变时撤销本次可逆决定。
