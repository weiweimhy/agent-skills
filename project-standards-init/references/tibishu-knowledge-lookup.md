# 可选：Tibishu 工程规范库按需检索与降级契约

仅在个人工程规范库能为当前初始化范围提供实际依据时，将其作为可选增强来源；它不是项目事实来源，也不阻塞初始化。

## 可用性检查与降级

1. 调用 `tibishu-notes` 检索能力前，确认该技能可用，并先读取进程环境变量 `TIBISHU_NOTES_PATH`（Windows 进程值为空时再查用户级环境变量），确认路径可读。
2. 未配置、路径不可读、技能不可用或检索失败时，不阻塞初始化：记录未读取的来源与原因，依据仓库事实、用户明确决定及本技能内置契约继续，不得声称已读取或应用笔记。
3. 若用户明确要求必须核对某篇特定笔记而当前不可访问，将该核对项标记为未完成并说明缺失输入，继续推进不依赖它的部分，不宣称整项要求已完成。

## 精确检索范围

- 遵循 `tibishu-notes` 的分层检索顺序：先看名称与 Blog front matter，确需落地规则时才读正文。
- 仅按仓库已证实采用或用户已明确选定的技术检索对应规范，**不要因为规范库里存在某技术笔记就假设当前项目已采用该技术**（例如路由库、状态管理库、特定 UI 组件库、跨端壳或截图工具）。
- 仅当当前范围涉及跨页面高频图标操作区，或本轮明确要求新增、替换或统一图标系统时，才检索图标系统规则；其用途是比较与记录决策，而非指定默认图标库。
- 除非用户明确要求且规则已证实具备跨项目普适价值，否则不修改工程规范库本身。
