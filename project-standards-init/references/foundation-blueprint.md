# 项目基座蓝图与裁剪契约

本参考指导如何构建**高信噪比、低维护成本、真正帮助 AI 提速**的项目基座。核心思想源自开源实战与实证共识（`Agent = Model + Harness`）：**把根 `AGENTS.md` 做成“导航图与加速器”，而不是“百科全书与禁令墙”。**

## 一、篇幅与信噪比预算

- **根 `AGENTS.md` 目标篇幅**：**50–120 行（约 2–4KB）**；除非需要压缩框架版本索引，否则避免超过 180 行。
- **准入标准（每行都要付上下文租金）**：只保留满足以下至少一条的内容——
  1. **代码里看不出**：跨文件不变量、历史踩坑（Gotchas）、环境/工具链反直觉行为。
  2. **能立刻省时间**：实测可用的快速验证命令、标杆样例路径、可直接复用的公共工具。
  3. **错一次代价高**：不可逆决策边界、禁止手改的生成产物、安全/兼容硬红线。
- **直接删除的内容（反模式）**：
  - 前沿模型已内化的通用常识（“写清晰代码”“变量名要有意义”“编写高质量单测”“遵循最佳实践”）。
  - 一眼可见的静态目录树流水账（极易过时，改目录即成误导源）。
  - 重复 `package.json` / `Makefile` / `CONTRIBUTING.md` 的全量列表（只列高频核心命令与陷阱，其余给链接）。
  - 用长篇反面禁令（“不要 X，不要 Y”）替代正向结构示例或自动化 Linter。

## 二、根 `AGENTS.md` 黄金骨架（按需裁剪）

以下 6 个模块按项目实际需要保留，**没有真实证据支撑的模块直接省略**，不要留空标题：

### 1. 项目定位与版本锚点（3–8 行）

- 一句话说清产品/仓库职责与核心运行形态。
- 标明真实技术栈及**关键主版本号**（例如 `Next.js 16 / React 19`、`Go 1.24`、`Swift 6.2`、`AGP 9 / Kotlin 2.x`），纠偏模型过时训练记忆；若仓库内或依赖包自带版本匹配的本地文档（如 `node_modules/next/dist/docs/`），直接给出指针。
- 新规划但尚未安装/落地的技术，在条目旁简明注明 `（计划/待实现）` 即可，无需在每个章节重复贴审计表。

### 2. 命令与快速验证闭环（最高价值模块）

用紧凑表格给出**可复制、实测存在、带防卡死/静默参数**的命令，明确区分快检与全量：

| 用途 | 命令 | 说明 / 耗时提示 |
| :--- | :--- | :--- |
| 单测（快检） | `<精确到单文件/单包的过滤命令>` | 日常开发首选；注明必须带上的 `-tags` / `--watchAll=false` |
| 类型 / 静态检查 | `<局部 typecheck 或 quiet lint 命令>` | 优先静默输出（仅失败打印），避免海量 warning 淹没上下文 |
| 构建 / 运行 | `<本地构建或非阻塞验证命令>` | 标出慢命令提醒与避免挂起终端的提示（如禁止裸跑 watch/dev server） |
| 代码生成 | `<唯一合法再生命令>` | 若仓库有生成物则必写 |

> **原则**：只写经仓库脚本、配置或实测确认的命令；未运行的命令注明“未实测”。

### 3. 加速导航：Where to Look First（替代长篇风格规范）

比起写 100 行抽象编码规则，给 AI 指明**参照物**既精准又不限制合理变通：

- **标杆样例（Golden Samples）**：按高频任务列出 2–5 个真实典范文件（例如“新增接口参照 `...`；新增页面参照 `...`”），并在存在历史技术债的仓库注明：**新规范与标杆样例优先于老旧代码**，避免 AI 模仿旧债。
- **公共基元与复用清单（Utilities / Primitives）**：列出 AI 最容易重复造轮子的内部工具、守卫函数、错误包装或共享组件入口。
- **只读生成产物（Generated / Managed）**：明确列出 `DO NOT EDIT` 路径（如 `*.pb.go`、`zz_generated.*`、构建绑定、工具托管资产）及其对应再生命令。

### 4. 隐形地雷与系统不变量（Gotchas & Invariants）

只写**不读本条就会踩坑**的规则，每条用 `约束 + 原因（Why）` 表达：

- 例：*测试不要用 `sleep` 同步，使用项目内置虚拟时钟（否则 CI 并发下会随机抖动）*。
- 例：*不要直接跑 `pnpm test`（默认 `--watch` 会挂起终端），改用 `pnpm test --run`*。
- 例：*禁止手动改 `gen/` 下文件，改完 schema 后执行 `make gen`（手改会在下次生成被覆盖）*。

### 5. 自主与确认边界（Always / Ask First / Never）

用三栏清晰边界**释放 AI 正常开发的自主权**，只锁住真正高风险的操作：

- **Always（放手直接做）**：遵循标杆样例实现功能、在授权范围内做可逆细节决策、补充针对性测试、运行局部快速验证并如实汇报结果。
- **Ask First（先给方案再动）**：修改公开 API/协议契约、数据库 Schema 或持久化迁移、全局架构/导航/主题替换、引入新第三方依赖、跨模块大重构。
- **Never（硬红线）**：读取或写入 `.env`/密钥/凭证、手改自动生成产物、把未运行的检查写成已通过、顺手重构与任务无关的模块。

### 6. 按需路由表（Before you... → Read ...）

用一张简洁索引表把深度知识下沉到单跳文档，避免根文件膨胀：

| 任务场景 | 先读 |
| :--- | :--- |
| 改动 UI / 页面样式 | `DESIGN.md`（或仓库已有设计文档） |
| 改动某复杂子系统 / 子包 | 对应子目录 `AGENTS.md` |
| 了解跨模块架构或数据流 | `docs/architecture.md`（仅当存在时） |
| 执行低频复杂流程（发版/迁移） | `.agents/skills/<name>/SKILL.md`（仅当存在时） |

> 仅链接真实存在或本轮确已生成的文件；绝不预留悬空链接。

## 三、分层拆分与多宿主加载

### 何时只建根 `AGENTS.md`，何时拆分？

| 仓库形态 | 推荐基座形态 | 说明 |
| :--- | :--- | :--- |
| 小型工具 / 单模块应用 | **仅根 `AGENTS.md`** | 无需为凑齐目录建一堆薄 `docs/` 文件 |
| 带独立视觉体系的 Web/App | 根 `AGENTS.md` + `DESIGN.md`（或已有设计文档） | 工程与视觉正交分离，互不污染上下文 |
| Monorepo / 多端 / 多子系统 | 根 `AGENTS.md` + 子目录 `AGENTS.md` | 子目录规则就近覆盖（如 `apps/web/AGENTS.md`、`pkg/storage/AGENTS.md`） |
| 含复杂外部集成 / 架构决策 / 长流程 | 按需补 `docs/architecture.md`、`docs/api-and-data.md`、`docs/decisions/` 或项目 `.agents/skills/` | 仅在信息量真实超出根文件承载时创建 |

### 跨宿主单一事实源

- 以 `AGENTS.md` 作为唯一事实源，不在多个规则文件中复制粘贴同一套规则。
- 若仓库已有 `CLAUDE.md` 或用户明确需要兼容 Claude Code，可将 `CLAUDE.md` 精简为单行 `@AGENTS.md` 引用（合并既有有效人工内容到 `AGENTS.md` 后再替换，不丢弃原有经验）。

## 四、增量刷新与“工具护栏 > 自然语言”

- **增量刷新纪律**：更新已有 `AGENTS.md` 或 `docs/` 时，先识别团队手写的有效踩坑与约定，仅做局部 diff 更新（或对自动维护段使用标记注释），绝不整篇覆盖抹除人工沉淀。
- **工具护栏优先**：格式化、import 排序、禁止 `as any`、禁止硬编码色值、模块依赖方向检查、死代码检测等确定性约束，理想位置是 **Linter / Typechecker / Pre-commit / 架构测试**（且在自定义报错中直接给出修复提示）。
- **按需提出高价值建议（不凑数）**：初始化/刷新结束后，仅当发现了**证据充分、会显著影响 AI 交付效率或安全**的真实缺口时，在汇总中简明列出（例如“缺少非 watch 单测脚本”“建议将硬编码颜色检查前移至 ESLint”“文档与真实命令冲突”）。缺少可选工具不强行算作缺陷。

## 五、交付前最小自检

- 根 `AGENTS.md` 是否精简高信号（目标 50–120 行，无通用废话与空壳章节）？
- 写入的每一条路径、依赖与命令是否均可在仓库事实或用户确认中追溯？未执行的命令是否如实标明？
- 是否保留了既有有效规范，且所有内部链接均可达？
- 修改的 Markdown 是否通过仓库可用 lint 检查（无工具时人工核对结构与链接）？
