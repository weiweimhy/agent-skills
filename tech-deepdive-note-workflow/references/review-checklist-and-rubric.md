# Review 检查表、三路只读总审阅模板与封版判定准则

## 一、单章精修 7 条过筛清单

1. **钩子检验**：遮住标题读前两段，是否以反直觉现象、矛盾字节或异常现场破冰？中段有无“顺直觉猜测 → 实测推翻”反转？结尾有无留真悬念而非空设问？
2. **连贯与“同题异角”检验**：与上下课过渡是否自然？跨课触及同一机制时（如静态布局 vs 动态调用链、单点手算 vs 批量扫描、事后转储 vs 事前审计），是否明确标出观察视角差异并互链呼应？
3. **实证与闭环检验**：所有地址/偏移/哈希/输出是否基于当前版本实测样本？更换编译参数后是否全部重新核对？是否明确区分磁盘静态线索与运行态动态现场？
4. **正常场景防误判边界**：攻防/异常/优化/内部状态分析中，是否说明了正常商业软件、合法编译器优化或常规系统组件也会呈现的相似特征，以及进一步确认所需证据？
5. **图解与动效检验**：最抽象的 1–3 个机制是否配有深色 SVG 动图或 Mermaid 图？SVG 静态帧是否无文字溢框/重叠？`<animateMotion>` 是否严格遵守写法 A/B 且过 `[xml]` DOM 校验？
6. **工具四要素与 GUI 声明**：交互调试步骤是否写清“停在哪里 → 动作前看什么 → 动作后哪个值变了 → 回答了什么问题”？未实拍截图的 GUI 步骤或缺失工具是否显式声明？
7. **元数据与全库 0 断链**：Frontmatter 字段是否齐备（`title == # H1`）？执行全库 `Invoke-DeepdiveNoteQA.ps1` 后链接、锚点与产物残留是否为 0？

## 二、终极三路只读总审阅模板（单会话按序或 `/swarm` 三路并行）

> **铁律**：三路审阅员**全程严格只读**，严禁修改目标笔记库或工作区隔离目录；一切临时复编复跑必须在 `$env:TEMP` 新建独立随机子目录，汇报前彻底删除并校验已清理。

### 轨道 1：深度 / 能力树与“伪闭环”审计员

- **审查目标**：对标领域高级工程师能力树，逐模块深读核心高阶章节及其配套 `.c/.cpp/.py/.lua` 源码，绝不吹捧。
- **重点严查 4 类伪闭环苗头**：
  1. **标题越级、核心缺代码**：名义讲完整重建/修复，但样本保留了明文接口或仅靠人工标注，配套脚本零行核心重构代码；
  2. **脚本严重过拟合样本字节**：用 `bytes.find()` 硬编码匹配自编样本在特定编译器优化级别下的固定机器码序列或魔法常量偏移；
  3. **玩具签名补丁冒充通用能力**：用寥寥几条固定字节替换就宣称完成通用还原，缺乏语法树/控制流/语义支撑；
  4. **跨工具链脚本未真机执行**：本机未装对应运行时或未实际启动目标工具，脚本仅过语法编译检查却写成完整实战。
- **交付物**：各模块深度评级与真实边界、原规划缺口逐项核实表（真打穿 vs 受限闭环）、当前架构下的高阶留白清单、前瞻/终审五维量化对比、能力划界（能硬刚什么 vs 哪里会撞墙）、毕业跃迁路线与**是否达到“最佳封版点”的明确判定**。

### 轨道 2：跨章连贯 / 同题异角 / 术语风格审计员

- **审查目标**：模拟真实读者从第 1 篇读到最后 1 篇，逐篇核对元数据、结构与跨章关系。
- **核查要点**：
  1. 总路线、模块 `README.md` 与正文课次间是否双向闭环，有无孤儿零入链文件、有无命名撞号；
  2. 重点易重章节组合（按专题逐组列对）的“同题异角”视角切割是否清晰；
  3. 写作口吻与钩子法是否贯彻到底，有无退化为干甩概念表；
  4. Frontmatter 字段规格与 `title == # H1` 全量比对；
  5. 全局指令语法（如统一 Intel 或统一 AT&T）、术语口径（如版本/地址标签/核心专有名词）与未实拍 GUI / 合规边界声明是否全程一致。
- **交付物**：严格按 `Blocker / Major / Minor` 分级的清单（每条附精确相对路径与行号实证）。

### 轨道 3：真机复编复跑 + SVG 动静态双检 + 全库自动化 QA 员

- **审查目标**：对关键章节（尤其是最新增补章节）在 `$env:TEMP` 做独立真机复验，并对全库跑自动化无盲区校验。
- **核查要点**：
  1. 将关键实验源码与脚本复制到 `$env:TEMP\qa_<随机>`，按文档原命令重新编译运行（带 `-Wall -Wextra` 等严格检查），核对二进制体积、段落偏移、指令机器码、CLI/调试器输出与正文是否 100% 一致，测完立即删净临时目录并确认残留为 0；
  2. 精读新画 SVG 的框内文本边距、箭头与数值一致性，并运行 `Invoke-DeepdiveNoteQA.ps1` 验证全库 `.svg` `[xml]` 0 错及 `<animateMotion>` DOM 0 双重偏移 / 0 `(0,0)` 静态锚点；
  3. 运行 `Invoke-DeepdiveNoteQA.ps1` 核查全库正式 `.md` 文件数、相对链接与 `#anchor` 断链数、旧名/禁用词/隐私路径泄露、实验子目录无构建产物残留、历史隔离区文件数零变动。

## 三、Blocker / Major / Minor 签发口径

| 分级 | 判定标准（满足任意一条即归入该级） | 发版处理原则 |
| :--- | :--- | :--- |
| **Blocker（阻断）** | ① 源码编译失败或实跑输出与正文核心结论矛盾；② 存在可误导实验或损坏数据的危险命令；③ SVG XML 解析报错或 `<animateMotion>` 双重偏移飞出画布；④ 全库存在本地链接或 `#anchor` 断链；⑤ 误写/污染历史只读隔离区或泄露个人敏感路径。 | **一票否决**：必须修复并复验清零后才可封版。 |
| **Major（重要）** | ① 存在“名义覆盖实则伪闭环”却未如实声明能力边界（把玩具补丁或未运行脚本宣传为通用实操）；② 同题多章内容大段重复未做视角切割；③ 关键实验目录残留未声明的临时编译垃圾；④ 正文缺失正常场景防误判边界或大段未声明的脑补缺失工具输出。 | **原则上须修补或显式标定边界**：要么补实逻辑，要么在正文与路线图中降格诚实划界，降为受限闭环备忘后再封版。 |
| **Minor（润色）** | ① 辅助说明页缺少 Frontmatter 或零入链；② 个别篇末缺少可点击下一课直链（已有文字引导）；③ 非核心摘要字段留存旧版简述；④ 个别日志标识或内联代码语法注释可更平滑。 | **不阻断封版**：可随手修，或在终审归档中集中记入 Minor 润色备忘留待后续批改。 |

## 四、“最佳封版点”停笔判定表

当需要判断一套长系列教程是否该继续写新课还是立即封版时，逐条对照以下 4 项条件：

| 判断维度 | 继续增补新课的信号 | 立即停笔封版的信号（最佳封版点） |
| :--- | :--- | :--- |
| **基础底座与单点覆盖** | 关键知识环存在整块断裂（例如缺运行入口机制、缺核心数据/指令底座或核心专题未实测）。 | 全部核心模块均已具备可独立复编/复跑的干净单点实验模型。 |
| **AI 沙盒边际收益** | 新增实验仍能依托本机标准开源工具链产生一手“意外实测红利”。 | 再往上扩（如强商业加密/超大规模外部框架/跨机内核调试）只能依靠数百行高度特化的“玩具自编代码”自圆其说，边际收益归零。 |
| **工具链与环境瓶颈** | 所需工具本机就绪，只差编写与实跑脚本。 | 剩余 20–30% 的鸿沟取决于商业 IDE、专职分析器、多机环境或真实庞杂的外部工程源码手感。 |
| **收口替代方案** | 读者还缺少看懂单点原理的最小实验。 | 改用“**明确的能力边界备忘 + 缺失环境自建路线 + 外部真实靶场/真实大型源码梯度清单**”收口，比多堆 10 篇教材价值更高。 |
